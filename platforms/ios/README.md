# Polymorph for iOS

One Swift package with two libraries, for SwiftUI apps on iOS 17 and macOS 14 or later:

- **`PolymorphTokens`**: the house pairings' tokens as Swift values. Each pairing is one
  `PMTheme`: every colour role (light and dark), the type steps, radii, shadows, the three
  densities, the four motion temperaments, and the pairing's metadata. The values come from the
  same theme engine as the web stylesheet, so a native screen and a web screen on the same
  pairing make the same decisions.
- **`PolymorphUI`**: the vocabulary's members drawn with SwiftUI, built on `PolymorphTokens`.
  Each member keeps its web name with a `PM` prefix (`PMBadge`), takes its spec's props as one
  generated value (`PMBadgeProps`), and reads every value from the theme. Every member with a
  file in `Sources/PolymorphUI` is written against the same contracts.

```swift
import PolymorphTokens
import SwiftUI

struct SaveButton: View {
  let theme = PMTheme.plain_neutral

  var body: some View {
    let density = theme.defaultDensity
    Text("Save")
      .pmTextStyle(theme.text.md)
      .foregroundStyle(theme.colors.accentContrast.color)
      .padding(.horizontal, density.space.s4)
      .frame(minHeight: density.controlHeight.md)
      .background(theme.colors.accentBg.color, in: .rect(cornerRadius: theme.radius.control))
      // The hit area, not the drawn height: at least 44 points whatever the density.
      .frame(minWidth: density.hitTarget, minHeight: density.hitTarget)
      .contentShape(.rect)
  }
}
```

A colour's `color` resolves by the colour scheme of the environment it is drawn in, so the same
value serves light and dark mode. `theme.preferredColorScheme` is the system's default mode, for
`.preferredColorScheme(_:)`.

With `PolymorphUI`, an app installs one pairing at its root and composes members, which read it
from the environment:

```swift
import PolymorphTokens
import PolymorphUI
import SwiftUI

struct TicketStatus: View {
  let status: String

  var body: some View {
    PMBadge(props: .init(children: status, icon: .time))
  }
}

// At the app's root:
TicketStatus(status: "Waiting").pmTheme(.terminal_petrol)
```

A view under no `.pmTheme(_:)` renders under `PMTheme.default`, the web's default pairing: the
system `design/defaults.json` names, with its default palette.

## Adding it to an app

The package lives in a subdirectory of this repository, so an app depends on it by path: a
checkout of the repository, or a git submodule of it. SwiftPM names a path dependency after its
directory, so the package is `ios`.

```swift
// Package.swift
dependencies: [.package(path: "../polymorph/platforms/ios")],
targets: [
  .target(
    name: "App",
    dependencies: [
      .product(name: "PolymorphTokens", package: "ios"),
      .product(name: "PolymorphUI", package: "ios"),
    ]
  )
]
```

In Xcode, choose **File › Add Package Dependencies…**, then **Add Local…**, and pick
`platforms/ios`.

## Names and units

- Lengths are points. A type size is the step's rem × 16 at the default text size; tracking is
  in points. `pmTextStyle` scales the size, the tracking and the line spacing with Dynamic Type,
  by the factor its text style scales by (body text for a text step, the largest title for a
  display step), the fallback system font included, and splits each line's extra height above
  and below it, as CSS's half-leading does, so a run of text is the step's line box per line.
  The line spacing is measured against the font that is drawn: the family when it is
  installed, the system font in the fallback design otherwise.
- Durations are seconds. Easings are cubic Bézier control points; springs are stiffness, damping
  and mass.
- A token is its path below its group, camelCased: `accent.bgHover` is `colors.accentBgHover`. A
  name that would start with a digit takes its group's name in front, or `s` on the space
  ladder: `chart.1` is `chart.chart1`, `text.2xl` is `text.text2xl`, `space.0` is `space.s0`
  (`space[0]` reads the same value).
- `default` is a Swift keyword, so the default spring is `spring.base`.
- A prop that takes a space step is a `PMSpaceStep` (`.s4`), however many members take one, and
  `space[step]` reads its length.
- The icon sizes and strokes are `theme.icon`, a `PMIconScale`; `PMIcon` is the vocabulary
  member `Icon` in `PolymorphUI`. `PolymorphUI` declares no name `PolymorphTokens` does, so a
  file can import both.
- A member is `PM` + its name, because SwiftUI already declares `Button`, `Text` and `Menu`, and
  its props are `PM<Member>Props`. An event's DOM event parameter is left out, because a native
  member has none to pass, and every closure is `@MainActor`, as a screen's actions are:
  `Button`'s `onClick` is `@MainActor () -> Void`.
- The hit target is 44 points at every density, Apple's minimum. It is a hit area, not a height:
  control heights are the density's, as on the web, so compact and comfortable still differ on a
  phone. A member shorter than `hitTarget` extends its hit area to it with `.contentShape` over a
  frame of at least that size, and keeps its drawn height. The area is on the part that takes
  the touch (a button, a segment, the colour well, the slider's drag), because a hit area on a
  container does not widen its children's; a field also opens on a tap anywhere in its area.
  Where the recipe keeps a smaller drawn box in the layout (an embedded button, a choosing field's
  opening button, a thumb, a link in a line), `pmHitRegion` lays the part out at its drawn size
  (the recipe's, or the part's own where it is larger, as wrapped text at the largest text sizes
  is) and centres a hit area of at least the target on it, past the edges the layout keeps, so the
  element VoiceOver's touch exploration finds is the hit target and the neighbours stay put. A
  UIKit view SwiftUI hosts (a text field, the compact date picker, a menu picker's button, the
  bar's buttons) is the size UIKit gives it: SwiftUI does not size it to a frame, so a text
  field's element is its text line inside the field's 44-point hit area. A text field names itself
  with `pmEntryName`, because SwiftUI speaks a field's title as its name on iOS and publishes none
  on macOS.

## What is not here

- The page texture (`texture.page`): no native toolkit draws the stylesheet's SVG noise tile. It
  is listed in `PMTheme.unsupported`.
- An inverse-tone table. On the web, `[data-tone="inverse"]` swaps the colour and chart roles
  alone; gradients, glows, shell surfaces and the glass surface keep the outer scope's value. A
  subtree under `.environment(\.colorScheme, …)` set to the other scheme swaps every dynamic
  value, those four included, so a view that draws the web's inverse tone resolves the colour
  and chart roles with `resolved(in:)` in the opposite scheme instead. The token document's
  `inverse` table lists them.
- `pmShadow` draws outer layers with SwiftUI's `shadow`, which has no spread and no inset; those
  values are in each `PMShadowLayer` for a view that draws them itself.
- A 44-point hit region for a control UIKit hosts that takes its own taps: the compact date
  picker, a menu picker's button and a colour well. UIKit sizes each as it does in every SwiftUI
  app and delivers its taps over the area it hit-tests to it, which no member's area widens. The
  simulator audit records each one whose area is under 44 points on an axis, and `ios.system` in
  `scripts/native-audits/thresholds.json` holds the count. They stay as they are by decision: a
  picker that behaved otherwise would differ from the same control in every other SwiftUI app.
  The number falls only when UIKit takes such a control's taps over 44 points. It rises only for
  a new fixture state that hosts such a control, named here. The run records them in these
  states: DatePicker's "filled", "open — the month grid, the value chosen", "clearable", "out of
  range — past maxValue, invalid", "a refused date — invalid", "hour — the hour on its own beside
  the date" (the date picker and the hour's menu button) and "datetime — the time beside the
  date" and "disabled", and TimeInput's "filled", "hour granularity" (the hour's menu button) and
  "disabled", each at the default text size, where UIKit takes the control's taps over less than
  44 points of height. A disabled control takes no taps, so it is measured by its bounds.

A text field's VoiceOver element is its editable line (`UITextField`, the multi-line text view),
as in any SwiftUI app, while the member's box takes the tap. The simulator audit holds the box,
which every text-entry member publishes, to 44 points, and finds no text field short of it.

## Working on it

From the repository root:

- `pnpm emit:native --target swift` rewrites `Sources/PolymorphTokens/Generated/`, and
  `pnpm emit:native --check` reports any file that is out of date. The freshness law
  (`packages/theme/src/native.test.ts`) fails when a generated file, or an example static in
  `Tests/PolymorphTokensTests/Examples/`, differs from what the engine emits.
  `packages/theme/src/swift-build.test.ts` runs, when `xcrun swift` exists, `swift build`,
  `swift test --filter PolymorphTokensTests`, and a type check of the token sources with the
  engine's probe pairing for macOS and the iOS Simulator.
- `pnpm native:contracts` rewrites `Sources/PolymorphUI/Generated/`, and `--check` reports a
  stale file.
- `pnpm gate:ios` checks `PolymorphUI` end to end: the contracts and the emitted examples are
  current, the laws hold, both libraries and the Relay example (`Examples/Relay`, described in
  [docs/native.md](../../docs/native.md)) build and test on macOS, and the package type-checks for
  the iOS Simulator, with the accessibility audit when a simulator runtime is installed. It needs
  Xcode; the audit needs an iOS simulator runtime (`xcodebuild -downloadPlatform iOS`, 8.5 GB for
  iOS 26.5), runs on an iPhone simulator of the device type and runtime the thresholds were
  measured on (the newest runtime when that one is not installed, which it says), and fails when
  it finds more defects, or records more system controls, than
  `scripts/native-audits/thresholds.json` allows ([docs/verification.md](../../docs/verification.md),
  "The simulator audit").

From this directory, `swift build` and `swift test` build and test both libraries.

[docs/theming.md](../../docs/theming.md) describes the token document the values are read from,
and [docs/native.md](../../docs/native.md) the screen contract the members are written against.
