# polymorph_tokens

The house pairings' tokens as plain Dart values. Each pairing is one `const PMTheme`: every
colour role (light and dark), the type steps, radii, shadows, the three densities, the four
motion temperaments, and the pairing's metadata. The values come from the same theme engine as
the web stylesheet.

Polymorph has no Flutter renderer. The package exists so that a Flutter app, or any Dart
program, can read the same decisions the web and the native packages read. It has no dependencies, Flutter included, and mapping a value to Flutter is one line:

```dart
import 'package:polymorph_tokens/polymorph_tokens.dart';

const theme = PMThemes.plain_neutral;
final density = theme.defaultDensity; // the density the system's axes select

final isDark = MediaQuery.platformBrightnessOf(context) == Brightness.dark;
final background = Color(theme.colors.accentBg.resolve(isDark: isDark).argb);
final padding = EdgeInsets.symmetric(horizontal: density.space[4]);
final radius = BorderRadius.circular(theme.radius.control);
final style = TextStyle(
  fontSize: theme.text.md.size,
  height: theme.text.md.lineHeight,
  letterSpacing: theme.text.md.tracking * theme.text.md.size,
);
```

| Value | In Flutter |
| --- | --- |
| `PMRgba` | `Color(rgba.argb)` |
| a length (`radius.md`, `space[4]`, `controlHeight.md`) | the `double` itself: a CSS px is a logical pixel |
| `PMTextStyle.lineHeight` | `TextStyle.height` |
| `PMTextStyle.tracking` (em) | `letterSpacing: tracking * size` |
| a duration (milliseconds) | `Duration(milliseconds: …)` |
| `PMEasing` | `Cubic(x1, y1, x2, y2)` |
| `PMSpring` | `SpringDescription(mass: s.mass, stiffness: s.stiffness, damping: s.damping)` |

## Adding it to an app

The package lives in a subdirectory of this repository, so an app depends on it by path, to a
checkout of the repository or a git submodule of it:

```yaml
dependencies:
  polymorph_tokens:
    path: ../polymorph/platforms/dart
```

or by git, naming the subdirectory:

```yaml
dependencies:
  polymorph_tokens:
    git:
      url: git@github.com:metamorph-labs/polymorph.git
      path: platforms/dart
```

## What is in it

| Path | |
| --- | --- |
| `lib/polymorph_tokens.dart` | The library: exports the types and the catalogue. |
| `lib/src/pm_theme.dart` | The types, written by hand: `PMTheme` and the classes it is built from, plus `resolve(isDark:)` and `inverse` on a dynamic colour, `argb` and `hex` on a colour, and `defaultDensity` and `defaultMotion` on a theme. |
| `lib/src/generated/` | One library per pairing and `catalogue.dart` (`PMThemes.plain_neutral`, `PMThemes.catalogue`, `PMThemes.named(system, palette)`). Generated by `pnpm emit:native`; never edit them. |

The catalogue holds each system with its default palette, the same set the web stylesheet loads
eagerly.

## Names and units

- Lengths are logical pixels. A type size is the step's rem × 16; line height is a multiplier
  and tracking is in em, as on the web.
- Durations, ambient periods and stagger are whole milliseconds. Easings are cubic Bézier control
  points; springs are stiffness, damping, mass and their damping ratio.
- A field is its token path below its family, camel-cased: `accent.bgHover` is
  `colors.accentBgHover`, `shell.topbar.bg` is `shell.topbarBg`. A name that would start with a
  digit takes its family in front: `chart.1` is `chart.chart1`, `text.2xl` is `text.text2xl`.
  The space ladder is a list: `space.4` is `space[4]`.
- `default` is a reserved word, so the default spring is `spring.base`, as in the Kotlin and Swift
  packages.
- A pairing is `system_palette`, each half camel-cased, the same name the Kotlin and Swift
  packages use: `PMThemes.plain_neutral`, and `acmeCorp_deepSea` for `acme-corp/deep-sea`.
- The hit target is 48 at every density, Flutter's `kMinInteractiveDimension`, which meets both
  phone platforms' minimums. It is a hit area, not a height: control heights are the density's,
  as on the web, so compact and comfortable still differ on a phone. A widget shorter than
  `hitTarget` extends its hit area to it (Material's `MaterialTapTargetSize.padded` does this)
  and keeps its drawn height. `PMTheme.floor` holds both floors (`controlHeight` 24, `hitTarget`
  48), and `floor.raised` lists the hit target raised at each density.

## What is not here

- The page texture (`texture.page`): no native toolkit draws the stylesheet's SVG noise tile. It
  is listed in `PMTheme.unsupported`.
- An inverse-tone table. On the web, `[data-tone="inverse"]` borrows the other mode's value for
  every colour and chart role, which is `colors.x.inverse` and `chart.x.inverse`, a swap of light
  and dark. Gradients, glows, shell surfaces and the glass surface keep the outer scope's value
  there, so an inverse-tone region swaps its colour and chart roles and nothing else; the token
  document's `inverse` table lists them.
- References arrive resolved. `radius.control` is the radius it names; only a member exception
  keeps the path it points at (`PMException.ref`).

## Working on it

From the repository root, `pnpm emit:native --target dart` rewrites `lib/src/generated/` and
`pnpm emit:native --check` reports any file that is out of date. The suite checks both: the
freshness law (`packages/theme/src/native.test.ts`) fails when a generated file differs from what
the engine emits, and `packages/theme/src/emit-dart.test.ts` runs `dart analyze --fatal-infos`
on the package when `dart` is on `PATH`, and checks that `pm_theme.dart` declares every field the
emitter writes. The rules `dart analyze` applies are listed in `analysis_options.yaml`, so it needs
nothing fetched.

[docs/theming.md](../../docs/theming.md) describes the token document the values are read from.
