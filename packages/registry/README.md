# @polymorph/registry

The canonical catalogue of the system, generated from source. The **registry** is one JSON
document that describes the whole system. It holds every member of the **vocabulary** (the closed
set of components) with its props, lawful variant × tone cells, states, tokens and the files that
must be installed with it, how each platform (`web`, `ios`, `android`) renders it, and whether each
web framework's vocabulary (`react`, `vue`, `svelte`, `solid`, `angular`) ships it. It also holds
the theme catalogue (axes, systems, palettes, colour roles, scales, every `--pm-*` property a theme
emits), the exception ladder and the red rules.

Every field is derived, not copied by hand. Props come from the exported TypeScript types, states
from each member's states fixture (`*.states.tsx`), token lists from its stylesheet, dependency
closures from the import graph, the platform and framework entries from `design/platforms/*.json`
and `design/frameworks/*.json`, the ladder from [docs/rules.md](../../docs/rules.md), and the
rules from `@polymorph/rules`. So the registry always matches the code. It is never committed, so
git holds no copy that can go stale.

The tools around polymorph learn the vocabulary only from the registry. The CLI, the MCP server,
the spec validator, the docs site and the workbench are **thin fronts**. They reshape registry
data and compute nothing the registry does not already hold.

## Command

`pnpm registry` (bin `polymorph-registry`) builds the registry from the working tree, validates
it against its own schema, and writes:

| File | Contents |
| --- | --- |
| `registry/registry.json` | The catalogue, schema id `polymorph-registry/1` |
| `registry/registry.schema.json` | Its JSON Schema, generated from the same description that validates it |
| `registry/system-card.md` | The **system card**: the whole vocabulary, compressed to fit an agent's context window |
| `apps/docs/src/fonts.gen.ts`, `apps/workbench/src/fonts.gen.ts` | Each app's font-loader map |

All of it is gitignored. It is regenerated by `pnpm install` (the root `prepare` script), by each
app's `predev` and `prebuild`, and by hand after you change a member, a theme or a rule.

## Entry points

| Import | What it is |
| --- | --- |
| `@polymorph/registry` | `buildRegistry(root)`, `renderRegistry`, `renderSystemCard`, the schema (`REGISTRY_SHAPE`, `SCHEMA_ID`), the install helpers (`fileClosure`, `fontsFor`, `fontPackage`), search and the types (`Registry`, `RegistryComponent`, `RegistryLaw`, …) |
| `@polymorph/registry/search` | `searchRegistry`, the ranking shared by the MCP server's `search_components` and the workbench's Components page. Browser-safe. |
| `@polymorph/registry/shape` | The small schema language the registry and the screen spec are written in: build a shape, `validate` a value against it, print it as JSON Schema. Browser-safe. |
| `@polymorph/registry/platforms` | The platform map's names (`PLATFORMS`), the shape of a `design/platforms/*.json` file and its law (`platformFaults`). Browser-safe. |
| `@polymorph/registry/frameworks` | The framework names (`FRAMEWORKS`), each framework's vocabulary and foundation package, the shape of a `design/frameworks/*.json` file and its law (`frameworkFaults`), and `vueBinding`, the reading of a React prop that the Vue, Svelte and Solid shells use. Browser-safe. |
| `@polymorph/registry/behaviour` | The behaviour contract: the grammar of a spec's `contract` fence (`parseStatement`, `readContract`) that the conformance law runs against each framework's members ([docs/conformance.md](../../docs/conformance.md)). Browser-safe. |
| `@polymorph/registry/agent` | The agent contract: the grammar of a spec's `agent` fence in its `## Agent` section (`parseAgentStatement`, `readAgent`), the closed lists it is written in, and the faults the registry build reports (`readAgentContract`). Browser-safe, so a browser test can read a spec's fence. |
| `@polymorph/registry/exceptions` | `auditExceptions`, which checks that each per-member exception in a system names a member that reads the token it re-points |

`buildRegistry` reads the repository it is given. The subpaths marked browser-safe import none of
its `node:fs` or TypeScript-compiler dependencies.

Every red rule in `laws` carries a `stage`. Stage 1 rules apply from the first line of
application code; stage 2 rules need the vocabulary and the exception ladder in place. Rules that
govern the vocabulary, and the CSS rules, have `stage: null`.

## Tests

In the `logic` vitest project:

```sh
pnpm exec vitest run packages/registry
```

- `src/registry.test.ts`: the registry validates against its own published schema, regenerates
  byte-identical on an unchanged tree, covers every member the galleries ship, and derives each
  field from the right source.
- `src/card.test.ts`: the system card's character budget, its floor, and that it names every
  member, rule, rung, axis and icon role. Any raise of the budget states its reason in that file.
- `src/search.test.ts`, `src/exceptions.test.ts`: the shared search ranking, and every
  per-member exception in `design/systems/*.json` checked against the members' token lists.
- `src/platforms.test.ts`: the platform law. Every member has an entry in every
  `design/platforms/*.json`, an adapted entry says how it renders, an absent one has a reason and
  a substitute that exists, no member is absent on the web, a native member that uses an absent
  one carries a reason, and no entry still holds the scaffold's `DECIDE` placeholder.
- `src/frameworks.test.ts`: the framework law. Every member has an entry in every
  `design/frameworks/*.json`, sorted by name, an absent entry says why, and no entry holds
  `DECIDE`; every package a shell imports is ranged with its framework, at a caret range or at the
  foundation's exact `@zag-js/core` for a Zag package; and the reading of a React prop in Vue.
- `src/behaviour.test.ts`: every spec's contract fences parse, and the grammar rejects what it
  does not define.
- `src/agent.test.ts`: every spec's agent fence parses, the grammar rejects what it does not
  define with the rule and the line, and each fault the registry build reports fails on a sample.
- `src/agent-staleness.test.ts`: the agent half of the spec-staleness law. The states, actions,
  secret states and `destructive when` of each member's agent fence are the ones its React member
  (`useAgentMember`) and its description (`agent`) register, in both directions; a member that
  registers has a fence, and one with a fence registers.
- `src/install.test.ts`: each published package's range is a caret on its own version, in
  `registry.packages` or in its framework's `vendor.frameworks.<framework>.packages`, and two
  manifests that range one package differently stop the build.
- `src/shape.test.ts`: the schema validator reads only a document's own keys.
