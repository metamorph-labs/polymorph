# @polymorph/solid

The Solid foundation. It re-exports [`@polymorph/engine`](../engine/README.md) whole and adds the
parts that exist only in Solid: the icon gateway, the machine adapter, the cells a member's scope
is written in, the keyed list, the slot conventions, the toast store, the page-transition
convention and the states fixture's types. It is the counterpart of
[`@polymorph/react`](../react/README.md) and [`@polymorph/vue`](../vue/README.md). The Solid
vocabulary, [`@polymorph/solid-ui`](../solid-ui/README.md), is built on it, and an application that
vendors Solid members installs it. A member imports this package and nothing deeper.

It contains:

- **The engine, whole.** The root is `export * from '@polymorph/engine'`, plus the engine's
  `charts`, `markdown` and `qr` subpaths. `anchorProps` is wrapped to name its focus handlers as
  Zag's Solid normalizer writes them (`onFocusIn`, `onFocusOut`).
- **The icon gateway**: `Glyph`, `BrandMark` and the `Icon` member, which `@polymorph/solid-ui`
  re-exports.
- **The machine adapter**: `useMachine`, adapted from `@zag-js/solid` 1.46.0, whose `send` applies
  an event before it returns, as the Vue and React adapters do; `watchEffect` and `afterRender`.
- **Cells and lists**: `createCell`, `createDerived`, `elementRef`, `elementList`,
  `useControlRef`, `Defaults`, the keyed list `Each` with `itemOf`, and `Keyed`, content made
  again when its key changes.
- **The slot conventions**: `claimSlot`, `resolveSlot`, `ResolvedSlot`, `scope`, `provide`,
  `ownerContext`, `IDENTITY` and `useDeparture`; `mergeParts` and `classes`; `useMediaQuery` and
  `MEDIA_QUERIES`.
- **The toast store**, the page-transition convention and the states fixture's types
  (`ComponentStates`, `StateEntry`).
- **The presences** (`@polymorph/solid/motion`): `usePresence` and `useKeyedPresence`, with the
  engine's motion environment, patterns and values re-exported by name. The subpath is for member
  internals, so it is not a root export.

`src/icon/Icon.tsx`, `src/icon/glyphs.ts` and `src/icon/icon.module.css` are generated by
`pnpm shells`; never edit them by hand. The rest of `src/` is written by hand.
[docs/shells.md](../../docs/shells.md#the-solid-foundation-polymorphsolid) describes every export.

## Entry points

Solid compiles JSX one way for a browser and another for a server, so the package ships three
forms, each under its own export condition:

| Import                             | In-repo (`exports`)        | Built (`publishConfig.exports`)                                                                                                    |
| ---------------------------------- | -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `@polymorph/solid`                 | `src/index.ts`             | `types`: `dist/types/index.d.ts`; `solid`: `dist/source/index.js`; `browser`, `import`: `dist/index.js`; `node`: `dist/server/index.js` |
| `@polymorph/solid/motion`          | `src/motion/index.ts`      | `types`: `dist/types/motion/index.d.ts`; `solid`: `dist/source/motion/index.js`; `browser`, `import`: `dist/motion.js`; `node`: `dist/server/motion.js` |
| `@polymorph/solid/icon.module.css` | `src/icon/icon.module.css` | — (in-repo only)                                                                                                                   |
| `@polymorph/solid/style.css`       | —                          | `dist/solid.css` (Icon's stylesheet, one file)                                                                                     |

`solid` is the source with its types removed and its JSX kept, which Solid's Vite plugin reads
first: the application's compiler writes it for the browser, a server render or hydration.
`browser` and `import` are the browser's build. `node` is the server's build, which writes strings
and imports no stylesheet, so plain Node loads it. Neither build is hydratable; an application that
hydrates compiles the source.

## Build

`pnpm --filter @polymorph/solid build` runs `vite build` (`vite.config.ts`, to `dist/`), then
`vite build --mode server` (to `dist/server/`), `tsc -p tsconfig.build.json` (the declarations, to
`dist/types/`) and `tsc -p tsconfig.source.json` (the source, to `dist/source/`), copies Icon's
stylesheet into `dist/source/icon/`, and runs `scripts/source.mjs`, which writes every relative
specifier in the source as the file it names (`./conventions/media.js`, `./icon/Icon.jsx`): a
bundler that reads an ES module package by Node's rules (webpack's `fullySpecified`) adds no
extension. Both builds keep Solid and every dependency external and write
one module per source module. No module imports `dist/solid.css`; `@polymorph/solid-ui`'s built
entry imports `@polymorph/solid/style.css`. The source form imports Icon's stylesheet beside
`Icon`, and the application's bundler compiles it.

## Dependencies and peers

| Peer       | Range    |
| ---------- | -------- |
| `solid-js` | `^1.9.0` |

Dependencies: `@polymorph/engine` (`workspace:*` here, published as an `npm:` alias of
`@metamorph-labs/polymorph-engine`), `@solid-primitives/keyed` `^1.5.3`, and `@zag-js/core` and
`@zag-js/utils` at exactly `1.46.0`, the version `useMachine` is adapted from.

The package is published as `@metamorph-labs/polymorph-solid` and installed as `@polymorph/solid`
through an npm alias (`"@polymorph/solid": "npm:@metamorph-labs/polymorph-solid@^1.0.0"`).
[docs/consuming.md](../../docs/consuming.md#a-solid-app) has the application's side.

## Tests

```sh
pnpm exec vitest run packages/solid/packaging.test.ts   # node: runs the real build
```

`packaging.test.ts` runs in the `logic` project. It builds `dist/` and checks that every export
target exists, the server's build loads in plain Node and renders a member to a string, the source
keeps its JSX and names only shipped files, the presences stay on `./motion`, the engine and Solid
stay external, and the declarations typecheck under a strict consumer. The conventions a member's
own tests reach only through a member are tested in
`packages/solid-ui/src/conventions/foundation.test.tsx` (the `solid` project).

See [docs/shells.md](../../docs/shells.md#the-solid-renderer) for how the members built on this
package are generated, and [docs/frameworks.md](../../docs/frameworks.md#from-react-to-solid) for
how a React prop reads in Solid.
