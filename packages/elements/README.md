# @polymorph/elements

The foundation of the elements: what every `poly-*` custom element shares. An element renders its
generated Solid member ([`@polymorph/solid-ui`](../solid-ui/README.md)) into itself, in the light
DOM, so the elements are a distribution of the Solid rendering and make no decision of their own.
[`@polymorph/elements-ui`](../elements-ui/README.md) holds the elements themselves, and
[docs/shells.md](../../docs/shells.md#the-elements-foundation-polymorphelements) says what this
package does for them.

## What it contains

- `src/element.ts`: `PolyElement`, the element base class, `define`, which turns a definition and a
  Solid member (and, for a member with a date or a time prop, the temporal codecs) into a custom
  element, `defineLazy`, which defines the tag before its member's code
  is loaded, and `restore`, which puts back the markup a page wrote. The base class takes the
  element's children into the member's slots, renders the elements of a document in document
  order once their code has loaded, follows a swap of its children, dispatches each callback as a
  `poly-*` event, and replaces a table's or a list's part with the element it renders. A prop
  named as a method every element inherits (Diff's `before` and `after`) has no property, so the
  method keeps working, and its attribute sets it (`inheritedMethod`).
- `src/loader.ts`: what a page with no build loads first: `defineAll`, which defines every tag at
  once, each loading its member's code the first time one of its elements renders, with
  `restore` and `toast`. It defines no element itself.
- `src/definition.ts`: what a definition is (`ElementDefinition`, `Codec`), and the names: `poly-`
  and the kebab name of a member, a part and an event (`tagOf`, `eventOf`), a prop's attribute
  and property, a slot's attribute.
- `src/codecs.ts`: how an attribute's text reads into a prop (`decode`): text, a number, presence,
  JSON, a union of literals, and ISO 8601 dates and times as the engine's values; a property's
  value as the member takes it (`coerce`), and the attribute text that reads back as a value
  (`encode`). It is for a script or a tool that reads values itself.
- `src/attributes.ts`: the same codecs as the element reads its attributes through. It imports no
  date type, and reads a date or a time through the temporal codecs it is given, so the date
  library loads only with a member that takes a date or a time.
- `src/temporal.ts`: the temporal codecs (`time`, `date`, `range`), which read ISO 8601 text as
  `@internationalized/date`'s values through the engine. The definition module of each member with
  a date or a time prop imports them and gives them to `define`.
- `src/events.ts`: `PolymorphEvent`, a `CustomEvent` with `waitUntil(promise)`.
- `src/fixture.ts`: the element-form states fixture's types, and `listen` and `holding`, which its
  `setup` uses.
- `src/host.css`: `:state(poly-host):not([hidden]) { display: contents }`, the rule that makes an
  element draw no box while it renders its member.
- `src/pending.css`: the rules for an element that has not rendered its member, generated by
  `pnpm shells`: a closed overlay's content stays hidden, and a table's and a list's parts lay out
  as the elements that replace them. Never edit it by hand.
- `src/icon/Icon.ts`: `<poly-icon>`, generated by `pnpm shells`. Never edit it by hand.
- `src/index.ts`: the entry, which imports the base layer (`@polymorph/recipes/base.css`), the
  host rule and the pending rules, so every element brings them, and re-exports the engine whole
  (`@polymorph/engine`, its charts, Markdown and QR subpaths), the Solid foundation's toast store,
  and the types the React vocabulary exports beside its members.

While an element renders its member it carries the custom state `poly-host`, so the elements need
Chrome 125, Safari 17.4 or Firefox 126. An element is not form-associated: each member's own input
posts.

## Entry points

| Import | In-repo (`exports`) |
| --- | --- |
| `@polymorph/elements` | `src/index.ts` |
| `@polymorph/elements/codecs` | `src/codecs.ts` |
| `@polymorph/elements/definition` | `src/definition.ts` |
| `@polymorph/elements/icon` | `src/icon/Icon.ts` |
| `@polymorph/elements/loader` | `src/loader.ts` |
| `@polymorph/elements/temporal` | `src/temporal.ts` |
| `@polymorph/elements/host.css` | `src/host.css` |
| `@polymorph/elements/pending.css` | `src/pending.css` |

The published build (`pnpm build:packages`, `vite.build.config.ts`) writes one module per source
module to `dist/`, with the two stylesheets beside them; its index also imports Icon's stylesheet,
`@polymorph/solid/style.css`. Solid, the Solid foundation, the engine and the recipes are external.
It depends on `@polymorph/engine`, `@polymorph/recipes`, `@polymorph/solid` and `solid-js`, as
dependencies, because a page has no Solid of its own. It is published as
`@metamorph-labs/polymorph-elements`.
