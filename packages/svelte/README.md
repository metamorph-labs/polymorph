# @polymorph/svelte

The Svelte foundation. It re-exports [`@polymorph/engine`](../engine/README.md) whole and adds the
parts that exist only in Svelte 5: the icon gateway, the slot conventions, the machine-prop
spelling, the toast store, the page-transition convention and the states fixture's types. It is
the counterpart of [`@polymorph/react`](../react/README.md) and [`@polymorph/vue`](../vue/README.md).
The Svelte vocabulary, [`@polymorph/svelte-ui`](../svelte-ui/README.md), is built on it, and an
application that vendors Svelte members installs it. A member imports this package and nothing
deeper.

It contains:

- **The engine, whole.** The root is `export * from '@polymorph/engine'`, plus the engine's
  `charts`, `markdown` and `qr` subpaths, so a member reaches every framework-free helper here.
- **The icon gateway**: `Glyph`, which draws a role's glyph from `src/icon/glyphs.ts`;
  `BrandMark`, a third-party mark from the engine's `BRAND_DRAWINGS`; and the `Icon` member, which
  `@polymorph/svelte-ui` re-exports.
- **A machine's props in Svelte**: `normalizeProps`, `attributes`, `mergeParts`, `chainHandlers`
  and `styleText`, over `@zag-js/types`.
- **The slot conventions**: `joinSlot`, `SlotScope`, `SlotOutlet` and `SlotText`, through which a
  member reads what a caller put in a snippet and hands it props, and `Render`, `bindSnippet`,
  `isBound` and `Portal`. Under Vite, a server render reads a slot through `svelte/server`
  (`src/conventions/server.ts`).
- **Effects and refs**: `watchEffect`, `afterRender`, `refList`, `useDeparture`, `useControlRef`,
  `useMediaQuery` and `MEDIA_QUERIES`.
- **The toast store** (`toast`, `useToasts`, `getToasts`, `subscribeToasts`, `removeToast`), the
  page-transition convention (`PageTransition`, `PageTransitions`, `usePageTransitionPending`) and
  the states fixture's types and holder (`ComponentStates`, `StateEntry`, `Overrides`, `Held`).
- **The presences** (`@polymorph/svelte/motion`): `usePresence`, `useKeyedPresence` and
  `useListPresence`, with the engine's motion environment, patterns and values re-exported by
  name. The subpath is for member internals, so it is not a root export.

`src/icon/Icon.svelte`, `src/icon/glyphs.ts` and `src/icon/icon.module.css` are generated by
`pnpm shells`; never edit them by hand. The rest of `src/` is written by hand.
[docs/shells.md](../../docs/shells.md#the-svelte-foundation-polymorphsvelte) describes every
export.

## Entry points

Both entries publish under the `svelte` export condition, with `types` and `default` beside it:

| Import                     | In-repo (`exports`): `types`, `svelte`, `default` | Built (`publishConfig.exports`)                                   |
| -------------------------- | ------------------------------------------------- | ----------------------------------------------------------------- |
| `@polymorph/svelte`        | `src/index.ts`                                    | `types`: `dist/index.d.ts`; `svelte`, `default`: `dist/index.js`  |
| `@polymorph/svelte/motion` | `src/motion/index.ts`                             | `types`: `dist/motion/index.d.ts`; `svelte`, `default`: `dist/motion/index.js` |

## Build

`pnpm --filter @polymorph/svelte build` runs `node scripts/package.mjs .`, which the vocabulary's
build runs too. A Svelte library ships its components as source, because the consumer's Svelte
compiles them for the browser and for a server render. So `dist/` holds every component as it is,
each TypeScript module as JavaScript (a rune module as `*.svelte.js`), every stylesheet as it is,
every relative import fully specified, and the declarations from `svelte2tsx`. Icon's stylesheet
ships beside `Icon.svelte`, and the consumer's bundler compiles it. There is no `node` copy: Node
cannot load a component.

## Dependencies and peers

| Peer     | Range     |
| -------- | --------- |
| `svelte` | `^5.46.4` |

Dependencies: `@polymorph/engine` (`workspace:*` here, published as an `npm:` alias of
`@metamorph-labs/polymorph-engine`) and `@zag-js/types` `^1.46.0`.

The package is published as `@metamorph-labs/polymorph-svelte` and installed as
`@polymorph/svelte` through an npm alias
(`"@polymorph/svelte": "npm:@metamorph-labs/polymorph-svelte@^1.0.0"`).
[docs/consuming.md](../../docs/consuming.md#a-svelte-app) has the application's side.

## Tests

```sh
pnpm exec vitest run packages/svelte/packaging.test.ts   # node: runs the real build
```

`packaging.test.ts` runs in the `logic` project. It builds `dist/` and checks that every export
target exists, every shipped file mirrors a source file, every relative import names a shipped
file, every component and rune module compiles for the browser and for a server render, the
presences stay on `./motion`, every imported package is declared, and the declarations typecheck
under a strict consumer. The presences and the slot conventions have browser tests in the
vocabulary (`packages/svelte-ui/src/conventions/presence.test.ts`,
`packages/svelte-ui/src/conventions/slotted.test.ts`, the `svelte` project).

See [docs/shells.md](../../docs/shells.md#the-svelte-renderer) for how the members built on this
package are generated, and [docs/frameworks.md](../../docs/frameworks.md#from-react-to-svelte) for
how a React prop reads in Svelte.
