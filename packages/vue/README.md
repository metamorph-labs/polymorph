# @polymorph/vue

The Vue foundation. It re-exports [`@polymorph/engine`](../engine/README.md) whole and adds the
parts that exist only in Vue: the icon gateway, the composables the generated members are written
with, the toast store, the page-transition convention and the states fixture's types. It is the
counterpart of [`@polymorph/react`](../react/README.md). The Vue vocabulary,
[`@polymorph/vue-ui`](../vue-ui/README.md), is built on it, and an application that vendors Vue
members installs it. A member imports this package and nothing deeper.

It contains:

- **The engine, whole.** The root is `export * from '@polymorph/engine'`, plus the engine's
  `charts`, `markdown` and `qr` subpaths, so a member reaches every framework-free helper
  (`spacingAttrs`, `paginationWindow`, `syncTriggerAnchor`, `devWarning`, …) here.
- **The icon gateway.** `Glyph` draws a role's glyph from `src/icon/glyphs.ts`, `BrandMark` draws
  a third-party mark from the engine's `BRAND_DRAWINGS`, and `Icon` is the member, which
  `@polymorph/vue-ui` re-exports. `glyphs.ts` holds each role's drawing as data, so no icon
  library is a dependency.
- **The composables and conventions**: `useControlRef`, `useMediaQuery` and `MEDIA_QUERIES`, the
  slot conventions (`slotted`, `slotNode`, `slottedElements`, `useTrackedSlots`, `useListening`,
  `useDeparture`, `definedProps`), `mergeParts` and `afterRender`.
- **The toast store** (`toast`, `useToasts`, `getToasts`, `subscribeToasts`, `removeToast`), the
  page-transition convention (`PageTransition`, `PageTransitions`, `usePageTransitionPending`) and
  the states fixture's types (`ComponentStates`, `StateEntry`).
- **The motion presence composables** (`@polymorph/vue/motion`): `usePresence` and
  `useKeyedPresence`, with the engine's motion environment, patterns and values re-exported by
  name. The subpath is for member internals, so it is not a root export.

`src/icon/Icon.vue`, `src/icon/glyphs.ts` and `src/icon/icon.module.css` are generated by
`pnpm shells`: `Icon` from its description (`packages/shells/src/members/icon.ts`), the stylesheet
from the React foundation's. Never edit them by hand. The rest of `src/` is written by hand.
[docs/shells.md](../../docs/shells.md#the-foundation-polymorphvue) describes every export.

## Entry points

In this repository the `exports` map points at source. `publishConfig.exports` points at the
build:

| Import                           | In-repo (`exports`)        | Built (`publishConfig.exports`)                                  |
| -------------------------------- | -------------------------- | ---------------------------------------------------------------- |
| `@polymorph/vue`                 | `src/index.ts`             | `types`: `dist/types/index.d.ts`; `import`: `dist/index.js`        |
| `@polymorph/vue/motion`          | `src/motion/index.ts`      | `types`: `dist/types/motion/index.d.ts`; `import`: `dist/motion.js` |
| `@polymorph/vue/style.css`       | —                          | `dist/vue.css` (Icon's stylesheet, one file)                     |

## Build

`pnpm --filter @polymorph/vue build` runs `vite build` (`vite.config.ts`), then
`vue-tsc -p tsconfig.build.json`, which writes the declarations to `dist/types/`.
`pnpm build:packages` runs it with the other published packages. The build keeps Vue and
`@polymorph/engine` external and writes one module per source module, so an application that
imports `Glyph` carries no `Icon`. No module imports `dist/vue.css`, so every entry loads in plain
Node. `@polymorph/vue-ui`'s built entry imports `@polymorph/vue/style.css`; an application that
renders `Icon` without the vocabulary imports it once itself.

## Dependencies and peers

| Peer  | Range    |
| ----- | -------- |
| `vue` | `^3.5.0` |

Dependency: `@polymorph/engine` (`workspace:*` here). The published manifest names it as an `npm:`
alias of `@metamorph-labs/polymorph-engine` (`scripts/publish-packages.mjs`).

The package is published as `@metamorph-labs/polymorph-vue` and installed as `@polymorph/vue`
through an npm alias (`"@polymorph/vue": "npm:@metamorph-labs/polymorph-vue@^1.0.0"`), so every
import keeps its `@polymorph/*` name. [docs/consuming.md](../../docs/consuming.md#a-vue-app) has
the application's side.

## Tests

```sh
pnpm exec vitest run packages/vue/packaging.test.ts   # node: runs the real build
```

`packaging.test.ts` runs in the `logic` project. It builds `dist/` and checks that every export
target exists, the stylesheet ships and no module imports it, both entries load in plain Node,
the engine and Vue stay external, the presence composables stay on `./motion`, every built module
mirrors a source file, every imported package is declared, and the declarations typecheck under a
strict consumer. The composables run under the Vue vocabulary's browser laws
([`@polymorph/vue-ui`](../vue-ui/README.md)).

See [docs/shells.md](../../docs/shells.md#the-vue-renderer) for how the members built on this
package are generated, and [docs/frameworks.md](../../docs/frameworks.md#from-react-to-vue) for how
a React prop reads in Vue.
