# Listing the plugin and the server

Polymorph's tools reach a coding agent through four public places: Anthropic's plugin directory,
OpenAI's plugin directory (shared by ChatGPT and Codex), the official MCP Registry, and the open
`skills` CLI. This guide says what each one reads, what this repository holds and generates for
it, and the steps that only the owner of the repository and its accounts can take.
[harnesses.md](harnesses.md) says how each harness uses the files.

Everything a listing reads is generated by `pnpm agents` from `packages/cli/src/plugin.ts` and
`packages/cli/src/skills.ts`, and `packages/cli/src/plugin.test.ts` holds it to each directory's
limits:

| File | Read by |
| --- | --- |
| `.claude-plugin/marketplace.json` | Claude Code's `plugin marketplace add`, the ChatGPT desktop app, and the `skills` CLI |
| `.agents/plugins/marketplace.json` | Codex's `plugin marketplace add` |
| `plugins/polymorph/.claude-plugin/plugin.json` | Claude Code and Anthropic's directory |
| `plugins/polymorph/plugin.json` | Codex and OpenAI's directory: the portable manifest, with OpenAI's fields under `extensions.com.openai` |
| `plugins/polymorph/.mcp.json`, `plugins/polymorph/mcp.json` | Claude Code, and Codex in the portable form |
| `plugins/polymorph/skills/` | Every harness, and the `skills` CLI |
| `plugins/polymorph/assets/` | The icon (the site's favicon) and PNGs drawn from it by `pnpm agents --icons` |
| `plugins/polymorph/README.md` | Anthropic's directory, as the listing's description |
| `packages/tools/server.json` | The MCP Registry |
| `PRIVACY.md`, `TERMS.md` | Every listing, by their URLs on `main` |

Each manifest names the release in the registry, and the plugin runs exactly that release of
`@metamorph-labs/polymorph` with `npx`. So the plugin of a release works once the package of that
release is public on npmjs.com, and every listing below waits on that upload.

The publisher in each manifest is `Metamorph, Inc.`, the copyright holder `LICENSE` names, with
`https://github.com/metamorph-labs` as its address. Each listing matches it against the verified
identity of the account that submits. The website and the documentation are links into the GitHub
repository, because the docs site has no public address yet. `PRIVACY.md` says that the tools run
on the user's machine, send nothing to Metamorph and collect nothing, which holds for the CLI and
the server: they make no network request of their own. `TERMS.md` is the MIT licence and its
warranty disclaimer. The owner reviews both before any submission.

## Anthropic's directory

The directory lists plugins on claude.ai, in Cowork and in Claude Code, which loads a listed plugin
through the user's account. It reads one plugin folder of a GitHub repository: here
`plugins/polymorph`, on `main`.

What it reads is in the plugin's `plugin.json` (name, display name, version, description, author,
homepage, repository, licence, keywords, the icon and the documentation, support, privacy and terms
URLs) and its README. Each is filled.

What its review is expected to hold for a reviewer, rather than refuse:

- **Runs a pinned npx package.** The server and the skills run
  `npx -y @metamorph-labs/polymorph@<version>`, pinned to the release as the directory requires.
  A pinned package is still held, because its dependencies resolve when it installs.
- **MCP server command wasn't read**, possibly: the server is started through `npx`, not from a
  file in the plugin.

The steps only the owner can take:

1. Publish `@metamorph-labs/polymorph` at the plugin's version to npmjs.com, as public.
2. Review `PRIVACY.md` and `TERMS.md`, and merge them to `main` with the plugin, so the URLs the
   manifest names resolve.
3. With a current Claude Code, run `claude plugin validate --strict plugins/polymorph` and
   `claude plugin validate --strict .` (the marketplace).
4. From a paid claude.ai plan (on Team or Enterprise as an Owner, or on Enterprise with the
   Directory permission), connect a GitHub account that can push to the repository, in the
   organization that submits.
5. At `claude.ai/directory/manage`, choose **Submit new**, then **Plugin bundle**. Give the
   repository `metamorph-labs/polymorph`, the plugin path `plugins/polymorph` and the branch
   `main`, and select **Validate**.
6. Answer the data-handling questions: the plugin reads and stores no personal data, sends data
   to no service, and keeps none. Check the contact email, select the acknowledgements, choose how
   new versions arrive (the GitHub push webhook needs an admin of the repository), and submit.

A new release reaches the listing when `main` holds the plugin of that release, which raises its
`version`.

## OpenAI's directory, for ChatGPT and Codex

The directory takes a ZIP of the plugin folder, uploaded at `platform.openai.com/plugins`. It reads
the portable manifest `plugin.json`, the skills in `skills/`, the MCP config `mcp.json` and the
icons in `assets/`. The listing fields are filled within its limits, `requires_local_executor` is
set because the skills run the CLI on the user's machine, and the manifest holds the review cases
OpenAI asks of a plugin with an MCP server: five a reviewer runs, each naming the tools it
triggers, and three the plugin declines. The plugin has no lifecycle hooks, which a public listing
cannot carry.

The server is a local process started over stdio, so the plugin is a desktop-only plugin:
installed from the ChatGPT desktop app and used in threads that run locally. OpenAI takes local MCP
submissions only from organizations it has allowlisted. That leaves two routes, and the choice is
the owner's, because an MCP server cannot be added later to a plugin first submitted as skills
only:

- **With the server.** Ask an OpenAI representative to allowlist the submitting organization for
  local MCP submissions, giving its organization ID. Once confirmed, choose **Skills only** in the
  portal and upload the ZIP with `mcp.json` in it.
- **Skills only.** The skills reach every tool through the CLI, so they work without the server.
  Upload a ZIP without `mcp.json`, and with `extensions.com.openai.review` removed from its
  `plugin.json`, because plugin-level review cases are for a plugin with one server.

The steps only the owner can take:

1. Publish `@metamorph-labs/polymorph` at the plugin's version to npmjs.com, as public.
2. In the OpenAI Platform organization that will own the plugin, complete individual or business
   verification, as an owner or with **Apps Management Write**.
3. Choose a route above, and for the server route, get the organization allowlisted.
4. Make the ZIP from the plugin folder of the release, leaving out what the other harness reads:

   ```sh
   cd plugins && zip -r ../polymorph-plugin.zip polymorph -x 'polymorph/.claude-plugin/*' 'polymorph/.mcp.json'
   ```

5. For the server route, record a walkthrough of the five review cases and give its URL in the
   portal (or as `review.demo_recording_url`), with release notes for the version.
6. Upload the ZIP, resolve the portal's findings, submit for review, and publish once approved.

A later release is a new ZIP of the same folder.

## The MCP Registry

The registry lists the server as `io.github.metamorph-labs/polymorph`. It holds metadata only: the
package itself is the npm package. `packages/tools/server.json` describes it (an npm package, run
over stdio, with the argument `mcp`), and `packages/tools/package.json` declares the same name as
`mcpName`, which the registry checks in the published package. Its version is the release's.

The steps only the owner can take, after each release's npmjs.com upload:

1. Install `mcp-publisher` (`brew install mcp-publisher`).
2. Log in with a GitHub identity that may publish under `io.github.metamorph-labs`: an Owner of the
   `metamorph-labs` organization, with a personal access token that can read organization
   membership (a classic token with `read:org`, or a fine-grained one with the organization's
   **Members** permission set to read):

   ```sh
   mcp-publisher login github --token <token>
   ```

   The interactive `mcp-publisher login github` grants only the personal namespace. Publishing from
   a GitHub Actions workflow with its OIDC token also proves the organization.
3. From `packages/tools`, run `mcp-publisher validate`, then `mcp-publisher publish`.

## The open skills CLI

`npx skills add metamorph-labs/polymorph` installs the four skills into the harnesses the CLI
knows. It finds them through `.claude-plugin/marketplace.json`: for each local plugin a marketplace
lists, it searches the plugin's `skills/` directory. Nothing is submitted, and nothing beyond a
public repository is needed.

## A Claude Desktop extension

An MCP bundle (`.mcpb`) carries a server with its `node_modules`, for Claude Desktop to install with
no `npx`. There is none: the tools depend on ESLint and its parsers, Stylelint, Prettier and
TypeScript, which a bundle would have to carry, and every harness above already starts the server
from the npm package.
